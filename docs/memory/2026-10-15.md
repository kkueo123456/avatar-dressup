# 用户系统与形象持久化方案决策

## 背景
Avatar Dressup 原本没有用户体系，形象数据只存在浏览器本地。需要增加：用户注册登录、形象保存到数据库、历史形象管理、Web3 铸造预留。

## 决策内容

### 1. 认证方案：用户名密码 + JWT Cookie
- **密码哈希**：`bcryptjs`（cost factor = 10），不存明文
- **会话**：`jose` 签发 JWT，存 HttpOnly Cookie（`avatar_session`）
- **鉴权**：`src/lib/auth.ts` 的 `requireAuth(request)` 统一在 API route 中使用
- **不上 OAuth**：产品早期，用户名密码足够，减少依赖

### 2. 数据库方案：Prisma + SQLite（本地），上线切 MySQL
- `User` 模型：id、username（unique）、passwordHash、createdAt
- `Avatar` 模型：id、userId（外键）、name、baseId、parts（JSON）、coverUrl
- Web3 预留字段：tokenId、mintStatus（enum）、chainId、contractAddress、ownerWallet、metadataUri
- 保留现有 `PosterJob` 模型不变

### 3. 保存流程 B：不自动跑海报
- 保存形象时只存 `AvatarState`（baseId + equipped JSON）+ 名称
- 封面图由用户手动触发（复用现有 PosterDialog + worker）
- 生成后 PATCH `/api/avatar/[id]` 更新 coverUrl

### 4. 恢复编辑：/create?avatarId=xxx
- `DressUp` 组件接收 `avatarId` prop
- 初始化时 `fetch(/api/avatar/${avatarId})`，通过 `store.replace()` 恢复状态
- 失败时在顶部显示恢复错误提示条，不阻断页面使用

### 5. 前端状态管理
- 新增 `authStore`（Zustand）：管理登录态、用户信息
- `AuthDialog`：登录/注册切换弹窗，暗色主题
- `TopBar` 改造：右侧显示登录按钮/用户菜单（我的形象/退出）

### 6. 形象列表页 /avatars
- Server Component 查数据库（Prisma），直接渲染
- `AvatarCard`：封面图、名称、铸造状态徽章、悬停操作（进入编辑/重命名/删除）
- 空状态：暗色插画 + 引导去创建

## 踩坑记录

1. **测试环境 `cookies()` 报错**：`next/headers` 的 `cookies()` 在测试里读不到请求头。
   - 解决：`requireAuth` 支持从 `request.headers.get('cookie')` 手动解析 token。

2. **并行测试数据冲突**：auth 测试的 `afterEach` 删除 `test_*` 用户，把 avatarCrud 的用户也删了，导致外键约束失败。
   - 解决：avatarCrud 测试用 `avatar_test_user` 前缀隔离。

3. **密码格式校验导致登录测试失败**：错误密码 `'wrong'` 只有 5 位，触发格式校验返回 400 而非 401。
   - 解决：测试用 `'wrong_password'`（>=6 位）。
